# Asteria 2.0 使用说明

启动 `D:\12345\Asteria\Asteria.exe`。这是便携程序，运行时保留整个 Asteria 文件夹。源码放在其中的 `Source` 文件夹。

1. 点击“新建对话”，选择项目工作目录。
2. 先选择 CLI，再选择该 CLI 返回的模型。Codex 与 DSH 都可以作为主模型；DSH 的同名模型会同时显示提供方。推理强度在模型旁选择。
3. 在底部输入消息。Enter 发送，Shift+Enter 换行；中文输入法选词时不会误发送。
4. 主模型可自行调用委派工具。你也可以明确指定，例如，使用 Codex 主模型时输入：“请派出 DSH 的 deepseek-v4-flash 阅读这个项目并给出关键模块说明，你收到结果后继续完成我的任务。”DSH 主模型同样可以委派 Codex 的 GPT 模型。
5. 子代理的 CLI、模型、任务、运行状态和结果显示在对应轮次的卡片里，点击展开。“工具与事件”可查看原始详情。
6. 点击“停止”会取消当前主模型及其子代理。需要权限时，界面提供本次请求的一次性允许或拒绝。

左侧会话列表支持搜索与切换。每个对话保留自己的工作目录、消息、模型与原生 CLI 会话；切换主 CLI 时会补充缺失的文字上下文。选择不同的工作目录会进入新对话。重启程序会显示历史，未完成任务不会自动重放。V1 任务保存在“V1 历史”中，只读展示。

左上角齿轮可以设置 CLI 路径、刷新模型，并切换 Mocha 深色或 Latte 浅色。程序优先自动发现本机 CLI，沿用它们现有的登录与配置。模型目录来自 CLI；目录中的模型是否能实际调用仍取决于对应账户和提供方。

当前支持 Codex、DSH。每个主轮次最多委派六个子任务，按顺序执行；Asteria 子代理不能继续派遣下一层 Asteria 子代理，每个子任务最长十分钟。它们共享当前对话的工作目录。DSH ACP 不提供强制只读沙箱，因此向 DSH 委派时不接受 `readOnly=true`。

对话通常保存在 `%APPDATA%\asteria\state`；外观及连接路径保存在程序的本机用户配置中。开发验收使用独立的 `ASTERIA_DATA_DIR`，与正常使用数据分开。
