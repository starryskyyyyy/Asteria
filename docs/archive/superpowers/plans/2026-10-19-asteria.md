# Asteria V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. User-directed adaptation: one GPT-6 Luna/high implementer performs the single end-to-end task; the parent owns code review and independent acceptance. Do not dispatch additional agents.

**Goal:** Deliver a usable portable Windows CLI workbench with real Codex/DSH task execution.

**Architecture:** Electron owns provider processes through adapters. A run manager coordinates sequential stages and persists normalized events; React consumes a narrow IPC bridge. Provider-native events are retained for inspection.

**Tech Stack:** Electron, React, TypeScript renderer, Node.js backend, atomic JSON/JSONL storage, node:test or an equivalent small test runner, Vite/esbuild as needed.

**Spec:** `docs/superpowers/specs/2026-10-19-asteria-design.md`

## Global Constraints
- Product/executable name: Asteria. Final destination: `D:\12345\Asteria`.
- Exactly one GPT-6 Luna / high implementer; parent reviews and accepts.
- Windows native window, Chinese UI, real installed CLI processes, no mock success.
- Existing login/config are reused; never expose secrets or mutate global model preferences.
- No user text interpolated into shell command strings; hide spawned helper windows.
- Only executor writes project files; planning/review read-only where supported.
- History view never replays a task; stop prevents every downstream stage.
- Workflow execution attempts: 1-3, default 1.
- V1 persistence is atomic JSON plus append-only JSONL; no native SQLite build dependency.

## Review Focus
1. Chinese/space/metacharacter paths and prompts remain exact arguments/stdin.
2. Cancellation during connect/start cannot race into a new running task or later stage.
3. Split JSON lines, stderr noise, malformed events and process exits yield deterministic state.
4. Pending approvals and unknown RPC requests never hang forever or auto-approve.
5. Partial/crashed persistence can reload safely without falsely completing or re-executing tasks.

### Task 1: Complete V1 desktop application

**Files (responsibility map; equivalent focused names allowed if documented):**
- `package.json`, lockfile, build config, `.gitignore`: reproducible dependencies, test/build/package commands.
- `src/main/cli-discovery.*`: installed command resolution and versions.
- `src/main/json-rpc.*`: buffered newline protocol, request IDs, timeout/error lifecycle.
- `src/main/providers/codex.*`: initialize, models, threads, turns, approvals, interrupt.
- `src/main/providers/dsh.*`: headless JSON events, process exit, cancellation.
- `src/main/run-manager.*`: direct/team state machine, bounded review loop, event correlation.
- `src/main/store.*`: atomic metadata, JSONL logs, interrupted-run reconciliation.
- `src/main/main.*`, `preload.*`: Electron window, narrow IPC, picker, cleanup.
- `src/renderer/App.tsx`, styles: connected Chinese workbench.
- `tests/*`: lifecycle/protocol/store/orchestration cases.
- `scripts/*`: repeatable CLI smoke and packaging if needed.
- `README.md`: Chinese setup, launch, tested capabilities and limits.

**Interfaces:**
- ProviderId: `codex | dsh`.
- Provider capability result: version, executable path, connected, models, capabilities, diagnostic.
- `ProviderAdapter.connect(): Promise<ConnectionInfo>`; `run(input: {cwd,prompt,model?,effort?,readOnly?}, onEvent, signal): Promise<{status,output,sessionId?,error?}>`; `stop(): Promise<void>`; `dispose(): Promise<void>`.
- Normalized event: `{id,runId,stage,provider,at,type,text?,raw?}`.
- `RunManager.start(request): Promise<runId>`, `stop(runId)`, `list()`, `get(runId)`, `subscribe(listener)`. Validate provider, absolute existing cwd, nonempty prompt and bounded attempts.
- Run states: `queued | connecting | running | awaiting-approval | completed | failed | cancelled | interrupted`; stages: `direct | plan | execute | review`.
- Store: `saveRun(run)`, `appendEvent(runId,event)`, `listRuns()`, `getRun(runId)`; recover nonterminal historical runs as interrupted.
- IPC only exposes task/connection/store/picker/approval APIs required by UI; validate renderer input in main.
